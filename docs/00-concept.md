# 00 · 기획 / 스코프 / 데이터 소싱 전략

## 한 줄 정의

지자체별로 파편화된 분리배출·대형폐기물 규칙을 **우리동네 기준으로 3초에 판단**해주고,
실제 신고·결제는 각 지자체 시스템으로 **딥링크로 넘기는** 정보 레이어.

## 왜 이 아이디어인가 (거지맵 DNA)

1. **당사자성** — 자취/이사할 때마다 겪는 본인의 페인.
2. **좁고 구체적 페인** — "이 매트리스 어떻게 버려? 얼마야?"
3. **정보가 사방에 흩어져 있음** — 지자체 245개가 규칙·수수료·신고시스템이 전부 다름.
4. **v1이 부끄러울만큼 단순** — 동네 하나(관악구) + 테이블 하나면 완성품.
5. **파편화 = 해자** — 모으는 것 자체가 귀찮아서 아무도 통합 안 함.

## 핵심 원칙

- **저작권 클린**: 수수료·품목 같은 *사실 데이터*는 저작권 대상이 아님.
  리스크는 (1) 남의 DB 통째 복제 (2) 이용약관/크롤링 금지 뿐 → 이 둘만 피한다.
  안전 소스 = 공공데이터(KOGL) · 지자체 조례/고시 · 크라우드소싱(직접 수집).
- **결제 없음**: PG·정산은 절대 소유하지 않는다. 신고/납부는 지자체 시스템 링크로 토스.
- **한 동네부터**: 전국 동시 확장 금지. 관악구 완성 → 수요 있는 동네부터 확장.

## 사용자 플로우 (v1 목표)

```
동네 선택(관악구)
  → 버릴 품목 검색("책상")
    → 결과 한 화면:
        · 수수료: 3,000원 (지자체 조례 기준)
        · 방법:   인터넷 배출신고 → 납부필증 부착 → 지정일 문앞 배출
        · [관악구 대형폐기물 배출신고 바로가기]  ← 여기서 우리 역할 끝(딥링크)
        · 로컬 꿀팁(크라우드소싱)
```

## 딥링크 확보 전략 (핵심 실무 리스크)

"지자체 → 신고 URL + 수수료"를 정규화해 주는 전국 단일 API는 **없다**.
따라서 자동 수집을 기대하지 않고 3층으로 채운다.

- **L1 손 큐레이션(초기)**: 지자체 신고 페이지 URL을 직접 DB에 입력. v1은 관악구 1건.
- **L2 부분 공공데이터**: 수수료·품목표는 공개 CSV(서울 데이터허브 등)로 보강, 없으면 고시 표 입력.
- **L3 크라우드소싱**: "우리 동네 링크 추가/정정" 제보로 확장.
- (운영) **링크 헬스체크 cron**: report_url 200 여부를 주기 점검해 link rot 방지.

## 경쟁 지형

- `여기로`, `빼기` 등 **대형폐기물 배출 트랜잭션 앱**이 이미 존재.
- 우리 웨지: 설치 없는 초경량 웹으로 **"버려도 되나 + 얼마 + 어디서"의 사전 판단**만 담당,
  트랜잭션은 그들에게 넘긴다(딥링크 병기).

## 데이터 모델 스케치 (다음 단계에서 확정)

- `region` — 지자체(관악구 등). `report_url`, `report_system`(자체/정부24/여기로/빼기), `source_updated_at`.
- `item` — 품목(책상, 매트리스…), 카테고리, 규격.
- `fee` — region × item → 수수료.
- `tip` — 크라우드소싱 로컬 꿀팁(region 단위).
