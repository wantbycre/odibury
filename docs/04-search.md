# 04 · 핵심 플로우 UI (검색)

## 화면

**동네 선택 → 품목 검색 → 규격별 수수료 + 배출방법 + 신고 딥링크**를
한 화면에서 보여준다. "3초 판단" 가설의 실체. (관악·강남·노원·영등포 4개 구 시드됨)

```
[어디버려 ♻️ · 서울 관악구 기준]
검색: [ 책상 ]
[책상][책장][서랍장]...        ← 이름/동의어(keywords) 매칭 칩
────────────────────────────
책상  (가구)
 수수료
  책상/컴퓨터책상(…)      6,000원
  h형 책상(…)            10,000원
 배출 방법: 인터넷/전화 신고 → 결제 → 배출번호 부착 → …
 💡 알아두면 좋아요: 저녁 6시~자정 배출 …
 [ 관악구 배출 신고하러 가기 ↗ ]   ← report_url 딥링크
```

## 구현

- `src/lib/supabase.ts` — anon 키 공개 읽기 클라이언트 팩토리(service_role 미사용).
- `src/app/page.tsx` — **서버 컴포넌트**. `force-dynamic` 으로 요청 시 조회.
  region(slug=gwanak) + item + fee + tip 을 병렬 fetch, 실패 시 fallback UI.
- `src/components/waste-search.tsx` — **클라이언트**. 소량 데이터를 전량 받아
  클라이언트에서 검색/필터(라운드트립 0). 품목 선택 → 결과 카드.

## 설계 메모

- 검색은 `name` + `keywords[]` 부분일치(대소문자 무시). 동의어(테이블/데스크 등)로 커버.
- 수수료는 규격(spec_label)별 여러 행을 저렴한 순으로 나열.
- 신고·결제는 소유하지 않는다 → `report_url` 로 지자체 시스템에 토스(정보 레이어 원칙).
- 다지역: 상단 `select` 로 동네 전환(현재 4개 구). 데이터가 소량이라 전량 로드 후
  클라이언트에서 지역·품목 필터(라운드트립 0). 규모가 커지면 `/[slug]` 라우트로 분리.
